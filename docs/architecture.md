# XPix-RV32 architecture
Unmodified PicoRV32 RV32I → native bus → 512 KiB BRAM + upstream simpleuart + status registers. External PCPI → registered 4×8-bit XPix ALU. No DMA, PS, DDR, cache or image codec. Both CPU configurations use counters/64-bit counters, all 32 registers, dual-port register reads, BARREL_SHIFTER=1, no M/C/IRQ, and misaligned/illegal instruction catching. Only ENABLE_PCPI and coprocessor instantiation differ.

rtl/picorv32.v and rtl/simpleuart.v are byte-identical copies of upstream files. Original firmware startup/linker files are preserved; firmware/xpix contains new application startup/linker and programs. The benchmark implementation is exposed by firmware/image_bench.c; actual build source is firmware/xpix/image_bench.c.

Code initialized in BRAM is synthesizable; uploaded frames are written at runtime. zcu102_top reserves synthetic clk, active-high reset, RX/TX and four LEDs. Physical differential clock buffering and actual verified pin constraints belong to board bring-up. OOC place/route verifies internal timing with 8 ns clock and 0.5 ns synthetic I/O budgets; it is not a pin-bound board bitstream.

The scalar kernels access one byte per iteration. Packed RV32I loads two words and implements four lanes with standard operations; XPix loads two words and executes one custom instruction (motion: two), storing one word. Functions are noinline, compiled -O2 -march=rv32i -mabi=ilp32; no compiler vector extensions. Each measurement uses the same cycle/instret read order and includes common call/counter boundary overhead, excludes byte comparison/output. Counter differences fit 32 bits for these runs; hardware 64-bit counters remain enabled. Primary benchmark uses deterministic moving squares, second dataset covers every unsigned byte pair. Python checks every output independently, not merely scalar vs XPix.
